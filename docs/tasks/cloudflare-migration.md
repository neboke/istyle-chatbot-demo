## プロンプト

あなたは私（Cloudflare を使うのは初めての開発者）の **メンター兼ペアプログラマー** です。
この作業の目的は、移行を終わらせることと、**私が仕組みを理解して次は一人でできるようになること** の両方です。

### 背景
- このリポジトリ（`neboke/istyle-chatbot-demo`）には、顧客への提案用デモ（`index.html`、`nangoku.html`）があります。
- 現在は **パブリック** リポジトリの GitHub Pages で公開していて、誰でも見られます。実在企業を題材にしたデモもあるため、閲覧を制限したいです。
- GitHub Pages ではベーシック認証をかけられないので、**Cloudflare Pages に移し、ベーシック認証をかけます**。そのあとリポジトリを **非公開** にします。
- まず `AGENTS.md` を読み、そこにあるルールに従ってください。

### ゴール（完了の条件）
1. 認証情報なしでアクセスすると `401` が返り、正しいユーザー名とパスワードを入れると両方のデモが表示される。
2. `main` に push すると自動でデプロイされる。PR のプレビュー URL にも認証がかかっている。
3. パスワードはリポジトリに含まれていない（Cloudflare の環境変数で管理している）。
4. 環境変数を設定し忘れたときは、**ページを表示せずエラーにする**（認証なしで公開される事故を防ぐ）。
5. リポジトリが非公開になり、GitHub Pages が止まっている。
6. 私が作業内容と仕組みを説明できる状態になっている。

### 進め方のルール
- **いきなり作業しない。** 各ステップの最初に「何を・なぜやるか」を3行ほどで説明し、私の了承を得てから進めてください。
- **アカウント作成・ログイン・ダッシュボードでの操作は私が自分で行います。** あなたは画面のどこを操作するかを案内し、私の報告や貼り付けたスクリーンショットを見て確認してください。
- **パスワードなどの秘密情報を、チャット・コード・コミットに書かないでください。** 私にも貼り付けさせないでください。
- 私の GitHub 権限は「Write」です。リポジトリの公開設定の変更、GitHub Pages の停止、GitHub App のインストール承認はできません。**オーナー（neboke）に頼む必要がある操作は、依頼文を作ってください。** 私がそれを送ります。
- 各ステップの最後に、理解を確認する質問を1つ出してください。私が答えたら、足りない点を補足してください。

### ステップ
**0. 前提知識（作業の前に）**
次の内容を、図か箇条書きで説明してください：静的ホスティング、CDN、Cloudflare Pages と Pages Functions（`_middleware.js`）の関係、ベーシック認証の仕組みと限界（パスワードを全員で共有する、HTTPS が必須）、環境変数と secret の違い、Production と Preview の違い。

**1. Cloudflare アカウントの作成**
- どのメールアドレスで作るかを、まずオーナーに確認する依頼文を作ってください（個人のアカウントにするか、会社のアカウントにするか）。
- 作成後、二要素認証を有効にするよう案内してください。

**2. 作業計画**
- リポジトリを読み、変更するファイル・作業の順番・オーナーへの依頼のタイミングをまとめた計画を出してください。
- **公開が途切れない順番** にしてください（Cloudflare 側で動作を確認してから、GitHub Pages を止めて非公開にする）。

**3. 実装（ブランチ `chore/cloudflare-pages`）**
- 公開するファイルを `public/` に移す（`AGENTS.md` や `.claude/` が公開されないようにするため）。
- `functions/_middleware.js` でベーシック認証をかける。ユーザー名とパスワードは環境変数 `BASIC_AUTH_USER` / `BASIC_AUTH_PASS` から読む。未設定のときは 500 エラーにする。比較はタイミング攻撃に配慮した方法にする。
- ローカル確認用の `.dev.vars` は `.gitignore` に入れる。
- `AGENTS.md` の構成と公開先の説明を更新する。
- 書いたコードは、私が1行ずつ説明できるまで解説してください。

**4. ローカルで確認**
- `npx wrangler pages dev public` で起動し、`curl` で次の3つを確認する：認証なし → 401、間違ったパスワード → 401、正しいパスワード → 200。
- `bash .claude/skills/review-demo/check.sh` も通す。

**5. PR**
- `AGENTS.md` の作業の流れに従って PR を作る。本文に確認した結果を書く。

**6. Cloudflare Pages の設定（ダッシュボードの操作は私が行う）**
- Git 連携で、このリポジトリを接続する（GitHub App のインストールにはオーナーの承認が必要なので、依頼文も作る）。
- ビルドコマンドは空、出力ディレクトリは `public`。
- 環境変数を **Production と Preview の両方に** secret として設定する。
- PR のプレビュー URL で、ステップ4と同じ3つの確認をする。

**7. 本番への切り替え（オーナーに依頼）**
- PR がマージされて本番で動くことを確認したあと、「GitHub Pages の停止」と「リポジトリの非公開化」をオーナーに依頼する文を作る。
- 切り替えたあと、旧 URL（`neboke.github.io/...`）が表示されないこと、新しい URL で認証がかかることを確認する。

**8. 振り返り**
次の内容をまとめた報告を作ってください。オーナーへの報告にそのまま使います。
- 新しい URL、ユーザー名とパスワードの共有方法（チャットに書かない方法で）
- 何をなぜ変えたか
- 詰まった点とその解決方法
- 私が新しく理解したこと（3つ）
- 今後の運用（パスワードの変え方、新しいデモの追加方法）
