# 新規デモの作成

AGENTS.md の「デモの品質基準」が前提です。先に読んでください。

## 1. ヒアリング（作り始める前に確認する）

次の項目が分からなければ、依頼者に聞いてください。推測で埋めないこと。

| 項目 | 例 |
|---|---|
| 題材 | 架空の会社か、実在企業を題材にした非公式デモか |
| 業種・商材 | コスプレ衣装のオーダー、中華料理店の宴会予約 |
| 見せたい体験（3つまで） | FAQ回答、見積もり受付、予約相談の受付 |
| 聞き取り項目 | 希望日、人数、予算、連絡先 |
| 管理画面で見せる効果 | 対応件数、削減時間、受付一覧 |
| ファイル名 | 英小文字とハイフン（例：`nangoku.html`） |

実在企業の場合は、公式サイトの URL と情報確認日も聞く。

## 2. 作り方

1. ブランチを切る：`git switch -c demo/<ファイル名から拡張子を除いたもの>`
2. `index.html` をコピーして、構造をそのまま使う。最初から書き直さない。
   - 残すもの：`header` / `.notice` / 2タブ（`view()`）/ チャット（`bot`・`send`・`actions`）/ 管理画面（`renderAdmin`・試算・受付一覧・履歴）
   - 差し替えるもの：ブランド名、配色（`:root` の変数）、商品データ、聞き取り項目（`fields`）、FAQ の回答（`answer()`）
3. 変わりやすい値（価格・期間・休業日など）は script の先頭の定数にまとめ、確認日と出典をコメントに書く。
4. 聞き取りの流れは「質問 → 確認画面 → 模擬受付 → 受付番号の発行 → 管理画面に反映」の順にそろえる。
5. 登録していない質問には、答えを作らずに「担当者／店舗への確認が必要」と返し、その件数を数える。

## 3. 完成の条件

- [ ] ブラウザで開くと、コンソールにエラーが出ない
- [ ] 想定する会話を最初から最後まで通して試し、管理画面の件数・受付一覧・履歴に反映される
- [ ] 不正な入力（過去の日付、0件、メールアドレスでない文字列）を入れると、案内文が出て先に進まない
- [ ] 「新しい会話」「体験データを消去」で状態がリセットされる
- [ ] 幅375px でも崩れない
- [ ] skill `review-demo` を実行して指摘がない

最後に、作ったファイル・試した会話・未確認の点を依頼者に報告し、PR を作る（AGENTS.md の「作業の流れ」を参照）。
