# デモのセルフレビュー

## 1. 機械チェック

リポジトリのルートから実行する。

```bash
bash .claude/skills/review-demo/check.sh
bash .claude/skills/review-demo/check.sh public/nangoku.html
```

- 引数なしの場合は、`public/` 内のHTMLを検査する。
- `public/` がない場合のみ、リポジトリ直下のHTMLを検査する。
- `NG` が1件でもあれば修正する。
- `要確認` は目で確認し、問題がないと判断した理由をPR本文に書く。
- この検査は補助的なもの。ブラウザの動作や認証の安全性を保証するものではない。

## 2. 目視チェックリスト

差分（`git diff main...`）と、ブラウザでの動作の両方を確認する。

**免責・表現**
- [ ] `.notice` にAGENTS.mdの4点（デモであること・架空/非公式・送信なし・情報確認日）がある
- [ ] 予約・価格・在庫・納期・アレルギーについて、確約する言い方になっていない
- [ ] 実在企業の場合、ロゴや写真を使わず、出典リンクがある

**安全性**
- [ ] ユーザーの入力は `textContent` でしか表示していない
- [ ] デモHTMLから外部への通信やデータの保存をしていない
- [ ] 外部リンクに `target="_blank" rel="noopener noreferrer"` がある
- [ ] 複数行で書かれたリンクやJavaScriptで生成するリンクも目視で確認した

**動作**
- [ ] 想定する会話を最初から最後まで通せる。途中で中止してメニューに戻れる
- [ ] 不正な入力が弾かれる（日付・人数・金額・メールアドレス）
- [ ] 管理画面の件数・受付一覧・履歴・試算がチャットの操作と合っている
- [ ] 同じ値の表記（金額・人数など）がチャットと管理画面で一致している
- [ ] 「新しい会話」「体験データを消去」で状態が正しくリセットされる

**見た目**
- [ ] 幅375px・768px・1280pxで崩れない
- [ ] キーボードだけでタブ切り替え・送信ができる

**変わりやすい情報**
- [ ] 日付・価格・期間は先頭の定数にまとまっていて、確認日がコメントにある
- [ ] その日付がすでに過ぎていないか

## 3. Cloudflareの認証確認

認証や公開設定を変更した場合、両方のデモで確認する。

- [ ] 認証なしでは401になる
- [ ] 間違った認証情報では401になる
- [ ] 正しい認証情報では200になり、デモを操作できる
- [ ] BASIC_AUTH_USERまたはBASIC_AUTH_PASSが未設定・空の場合は500になり、デモを表示しない
- [ ] ローカル・Preview・Productionで、それぞれ必要な確認を実施した
- [ ] 全URLに認証がかかり、認証を省略するURLがない
- [ ] Functionsの利用上限時はFail closedになる設定を確認した
- [ ] 秘密情報がGit管理対象やpublic内に含まれていない

秘密情報をコマンド履歴、画面共有、スクリーンショット、PR本文に残さない。
未実施の環境や項目は、合格扱いにせず報告する。

## 4. 報告の形式

```
## レビュー結果：<ファイル名>
- check.sh：NG N件 / 要確認 N件（それぞれの判断理由）
- 目視：問題なし / 指摘 N件
  1. <場所> <内容> → <修正案>
- 認証：ローカル・Preview・Productionごとの確認結果
- 未確認：<確認できなかった点と理由>
```

指摘を直したら、関係する検査と動作確認を再度行う。
