# デモのセルフレビュー

## 1. 機械チェック

```bash
bash .claude/skills/review-demo/check.sh            # 全デモ
bash .claude/skills/review-demo/check.sh nangoku.html
```

- `NG` が1件でもあれば修正する。
- `要確認` は目で確認し、問題がないと判断した理由を PR 本文に書く（例：`innerHTML` には固定の SVG しか入れていない）。

## 2. 目視チェックリスト

差分（`git diff main...`）と、ブラウザでの動作の両方を確認する。

**免責・表現**
- [ ] `.notice` に AGENTS.md の4点（デモであること・架空/非公式・送信なし・情報確認日）がある
- [ ] 予約・価格・在庫・納期・アレルギーについて、確約する言い方になっていない
- [ ] 実在企業の場合、ロゴや写真を使わず、出典リンクがある

**安全性**
- [ ] ユーザーの入力は `textContent` でしか表示していない
- [ ] 外部への通信やデータの保存をしていない

**動作**
- [ ] 想定する会話を最初から最後まで通せる。途中で中止してメニューに戻れる
- [ ] 不正な入力が弾かれる（日付・人数・金額・メールアドレス）
- [ ] 管理画面の件数・受付一覧・履歴・試算がチャットの操作と合っている
- [ ] 同じ値の表記（金額・人数など）がチャットと管理画面で一致している
- [ ] 「新しい会話」「体験データを消去」で状態が正しくリセットされる

**見た目**
- [ ] 幅375px・768px・1280px で崩れない
- [ ] キーボードだけでタブ切り替え・送信ができる

**変わりやすい情報**
- [ ] 日付・価格・期間は先頭の定数にまとまっていて、確認日がコメントにある
- [ ] その日付がすでに過ぎていないか

## 3. 報告の形式

```
## レビュー結果：<ファイル名>
- check.sh：NG 0件 / 要確認 N件（それぞれの判断理由）
- 目視：問題なし / 指摘 N件
  1. <場所> <内容> → <修正案>
- 未確認：<確認できなかった点と理由>
```

指摘を直したら、もう一度 1 から確認する。
